# Explicit Lens native source inputs

This library owns the historical unpublished-cohort proof and the separate
published control. The current stable target reads the committed registry lock.
The hosted `fetch-renderer` command reuses the fixed renderer admission and
emits its own original archive and receipt for the stable compatibility matrix.

The fixed table binds the independently read original AF archive and native
proof to one source/tree/run/attempt and all original required jobs. Only the
named AF documentation/Lens bootstrap hold is deferred. This phase is not whole
producer acceptance or registry provenance; every original gate must join later.
Engine14 RC and Foottrace2.1 retain their real public registry identities, with
absent registry gitHead recorded as unknown.

The facade is the only external entry. Private modules own admission, bounded
archive reads, existing-token transport, temporary source projection and actual
installed identity checks. No arbitrary producer, alternate credentials, retry,
rebuild, alias, peer rewrite or registry/native fallback is supported.

The source lock admits exactly the three projected cohort archives. The distinct
packed-consumer lock additionally admits only this checkout's original Lens
archive and the selected original renderer archive, with manifest, version,
locator, SRI and byte-digest joins. It exposes no caller-supplied file allowlist;
unknown inputs still refuse in both roles.

Effect-free tests live beside these units. Full installs/builds/runtime/consumer
gates belong to hosted CI; a green data observation alone cannot activate them.

The v2 receipt adds the independently reviewed original UI renderer.
`renderer.mjs` binds the fixed successful producer run, complete four-job set,
original artifact and tested-tree parents. `archive_data/renderer.py` accepts
only its thirteen-member dependency-security format; it does not invent an
AF candidate protocol or committed UI lock. The generated audit lock stays
inert. The source-mode projection still changes only three development locators;
the renderer original is consumed only by the separate packed matrix. Source
development uses renderer 2.1.0 and the packed matrix also exercises the 1.0.1 native-source API; the
original historical replay fixtures remain unchanged.

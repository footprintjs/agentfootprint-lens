# Lens compatibility inputs

The stable source and packed consumer gates read the committed registry
cohort. The compatibility inputs here serve two distinct jobs.

- `renderer.mjs`, `transport.mjs` and `archives.mjs` admit the reviewed
  original UI renderer archive. Its fixed run and tested parents, complete
  job set, original package and manifest must agree. The bounded archive
  reader treats the generated audit lock as evidence. The original
  thirteen-member artifact and twenty-member tarball are read as data.
- `materialize.mjs` and `gates.mjs` run the independently installed
  historical published commentary CONTROL. Its own temporary strict
  lock pins AgentFootprint 14.7.2, FootPrint 12.3.0, Foottrace 1.11.1 and
  Explainable UI 1.0.1. Its checked-out source inventory, resolved lock
  and installed versions are checked before and after each gate.

The facade is the only external entry. Private modules own admission, bounded
archive reads, transport for the fixed renderer producer and installed identity
checks. The CLI is hosted-only. It has no arbitrary producer, alternate
credentials, retry, rebuild, alias, peer rewrite or registry/native fallback.

The v2 receipt binds the separately reviewed renderer original to the fixed
successful producer run, complete four-job set, original artifact and
tested-tree parents. `archive_data/renderer.py` accepts only its thirteen-member
dependency-security format. The generated audit lock stays inert.

The source lock uses the stable registry cohort. The separate packed matrix
checks that cohort in its strict consumer lock, and tests this checkout's
original Lens archive with the selected renderer archive. Source development
uses renderer 2.2.0, and the packed matrix also exercises the 1.0.1
native-source API. The original historical replay fixtures remain unchanged.

Adjacent tests check renderer admission and the control's source inventory
without installing packages. Full installs, builds, runtime and consumer gates
run in hosted CI.
